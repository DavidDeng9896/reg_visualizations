## 1. 30 秒定位

**Insight Analysis 是给生物药 / 实验室科学家用的数据分析工作空间。**

客户把 CSV、Excel 或数据库里的实验表导进来，在同一份 **Analysis（分析）** 里完成：

1. 清洗、拼接、派生列  
2. 科学作图（柱 / 线 / 散点 / 箱线 / 饼 / 热图 / 大数字；含 4PL 拟合）  
3. 用流程图把分析步骤固化成可复现管线  
4. 需要时用 Python（Custom Code）做 Prism 级统计  
5. 用 AI 对话完成「导入 → 清洗 → 出图 → 报告」  
6. 把关键表和图钉到 **看板**，给项目会 / 周报看

一句话对客户：

> 「不是又一个 Excel，也不是只能出图的 Prism。它是实验室分析的**工作区 + 流程图 + 科学图 + 统计代码 + AI**，分析过程可复现、可复盘、可上墙。」

明度产品叙事：左侧导航已预留注册、化合物、序列等模块，**当前可售可演示的是「数据分析」**。把它讲成科学数据管理平台里已经落地的分析层，而不是一个孤立作图工具。

## 2. 适合谁、解决什么痛点

### 2.1 目标客户

| 角色 | 他们每天在做什么 | 我们帮什么 |
| --- | --- | --- |
| 抗体发现 / 筛选科学家 | ELISA、SPR/BLI、克隆排序 | 多表 Join、KD 对比图、候选排序、报告 |
| 细胞株开发 | 滴度、活率、稳定性趋势 | 过滤 + 折线/箱线 + 看板 |
| 体外生物分析 | 剂量反应、EC50/IC50、孔板 | 4PL 拟合、热图、效价比较 |
| 体内药效 / 耐受 | 瘤体积、体重、分组 | 分组折线、组间比较（statlib） |
| 工艺 / 生物分析 | 批数据、SQL 库、周报 | SQL 直连、看板、分析报告 |
| 信息化 / 数字化负责人 | 要可审计、少 Excel 飞书群 | 步骤链可复现、服务端落库 |

### 2.2 客户痛点 → 产品回应

| 客户原话 | 回应 |
| --- | --- |
| 「结果散落在几十个 Excel 里，对不上版」 | 一份 Analysis 管表、视图、图、步骤；改数会标记下游过期并重跑 |
| 「Prism 图很好看，但流程没法给同事复现」 | 流程图把 Filter / Join / 计算列 / Python 固化；别人打开同一条链 |
| 「CRO 回一个多 Sheet 的 xlsx，我要手工对齐」 | Excel 选表导入；或 AI 上传附件走清洗 + Join |
| 「周会要一张看板，不要再翻十个文件」 | 看板跨 Analysis 钉表、钉图、钉 Python 图、钉外链 |
| 「能不能让 AI 先出一版，我再改」 | 右下角 AI：计划 → 工具执行 → 图表产物 → 可选生成报告 |
| 「统计要 t 检验 / ANOVA / 4PL」 | 图上原生 4PL；更深的 Prism 方法走 Custom Code + statlib（20 种） |


## 4. 功能模块（交流用）

每节结构：**一句话价值 → 客户能做什么 → 演示时点哪里 → 边界**。

### 4.1 分析工作区（Analysis）

**价值：** 一次实验/一次课题 = 一份分析，而不是一堆散文件。

客户能做：

- 新建分析、重命名、删除、按名称搜索
- 按项目 / 部门筛选
- 打开后在 **Workspace** 看表和图，在 **Flowchart** 看步骤拓扑
- 侧栏树浏览所有表、视图、图表、分析报告节点
- **一键 Demo**：Iris、96 孔板剂量反应、体重-体长等通用示例
- **生成项目示例数据**：三套抗体业务分析（含完整步骤链和七种图）

**边界：** 分析之间默认独立；跨分析汇总走看板，不是把多个 Analysis 合成一个文件。

---

### 4.2 数据怎么进来

**价值：** 科学家日常拿到的表，都能进工作区。

| 入口（界面文案） | 能力 | 售前说法 |
| --- | --- | --- |
| Import CSV | 上传 `.csv` 成新表 | 最稳妥的开场导入 |
| Import Excel | `.xlsx` / `.xls`，选工作表 | 对 CRO 回传、实验记录本导出 |
| Import from SQL | Postgres / MySQL / MariaDB，或查本分析已有表 | 工艺/信息化客户必讲：库表直连、可预览、可定时刷新 |
| Combine tables | Join（左/内/右/全）或 Append（追加） | 「两张表按克隆号拼起来」 |
| AI 附件 | 对话里上传 CSV / Excel 等 | 「把文件丢给 AI，让它导入并分析」 |

**不要讲成已上线：** From Registry、From Plate（菜单能看见，标注后续版本）。

SQL 可讲的细节（信息化在场时）：保存连接、浏览 Schema、在线写 SQL、预览约 50 行、约 2 分钟自动刷新。适合「我们结果已经在库里」的客户。

---

### 4.3 表格（类 Excel，但可审计）

**价值：** 能改数、能筛、能派生，但改完下游知道要重跑。

客户能做：

- 类 Excel 网格：排序、筛选、列显隐、行选择
- **编辑数据** 会话：改单元格 → **确认修改** 才写回；会话内撤销/重做
- 导出 CSV
- 从表直接 **创建图表**
- 视图级过滤：等于 / 不等于 / 大于小于 / 区间 / 包含 / 空值
- 视图转换：选列、重命名、派生列、去重、排序
- 含过滤/转换的视图只读，可 **提升为表**（物化一份新表）
- 化学结构列（SMILES 等）可在格子里画分子结构

跟 Excel 的差异（主动讲，避免被当成「又一个表格」）：

- **不做** 单元格合并、Excel 公式引擎、富文本单元格
- 分析步骤留在流程图里，而不是藏在某个 sheet 的公式里
- 源表可编辑；加工后的视图不偷偷改上游

---

### 4.4 流程图（分析过程可复现）

**价值：** 给 QA、给同事、给半年后的自己看「这张图是怎么算出来的」。

当前可执行步骤（演示只加这些）：

| 类别 | 步骤 | 客户语言 |
| --- | --- | --- |
| 清洗 | Filter table | 去掉对照孔、低信号、失败批次 |
| 清洗 | Hide columns | 隐藏不需要展示的列 |
| 变换 | Add computed column | 算比率、对数浓度、命中标记 |
| 合并 | Join tables | 按克隆号 / 样品号拼宽表 |
| 合并 | Union tables | 多批次追加 |
| 代码 | Custom code | Python 统计、拟合、自订图 |
| 输出 | 分析报告 | 独立报告节点，给评审看 |

交互：节点可拖位置；点节点进 Workspace；从输出端口拖到空白处添加下一步。侧栏改结构，画布主要用来看布局。

上游改数或 SQL 刷新后，下游步骤会标成 **过期（stale）**，可重跑。这是对「可重复分析」客户（QA、注册、工艺）的核心卖点。

**边界：** 透视表、窗口函数、分箱、标准曲线插值步骤等仍在目录规划中，**不要在 Demo 里点开承诺**。去重/排序目前是**视图转换**，不是流程图步骤。

---

### 4.5 科学图表

**价值：** 实验室常用图种齐，配置对齐科研作图习惯（对标 LabKey / Benchling 分析图）。

| 图种 | 典型客户说法 | 要点 |
| --- | --- | --- |
| 柱状图 Bar | 「按克隆看 OD / 滴度」 | 聚合、分组/堆叠、水平柱、误差棒 SD/SEM |
| 折线图 Line | 「剂量反应、生长曲线」 | 多 Y、次轴、**4PL / 线性 / 二次**拟合 |
| 散点图 Scatter | 「KD vs 表达量」 | 颜色/形状/大小、抖动、误差棒、拟合 + 套索打标 |
| 箱线图 Box | 「组间分布」 | 分类 X、显示全部点/离群点 |
| 饼图 Pie | 「构成比」 | 环形、显示百分比 |
| 热图 Heatmap | 「96 孔板 / 条件矩阵」 | 行列排序/聚类、单元格标注 |
| 大数字 Big number | 「看板 KPI」 | 关键指标、SI 缩写 |

共性能力（几乎每张图都能讲）：

- 右侧 **CONFIGURE / STYLE** 两栏：映射字段 vs 标题/边距/图例/色板
- 轴：自定义标签、线性/对数、自动/手动范围、X/Y 交换
- 表和图同一屏，图可放在表的上/下/左/右
- **导出 PNG / PDF**（悬停图右上角）
- Line / Scatter：**MODEL TABLES** 看拟合参数
- 散点/拟合场景：**套索打标** 后可排除点再拟合
- 图种可切换，能保留的字段映射会尽量保留

Custom Code 产出的 Plotly 图是独立产物（没有 CONFIGURE 面板），可进看板和报告——适合「这张图必须完全按我们 SOP 画」的场景。

### 4.6 看板（Dashboard）

**价值：** 把科学家工作区里已经验证过的表和图，钉成一页给项目会。

客户能做：

- 新建 / 重命名 / 删除看板
- 添加组件：**Insight 表**、**Insight 图表**、**Custom Code Python 图**、**外部链接**
- 跨多个 Analysis 挑选已有表和视图（不是重做分析）
- **编辑布局**：拖拽网格、多选删除
- 刷新后布局和内容仍在（企业部署走服务端库）

**话术：** 看板不是第二个 Excel，是「已经算完、已经画完」的展示层。分析仍在 Analysis 里改，看板上看到的是选定快照式组件。

---

### 4.7 Custom Code 与统计（对 Prism 用户）

**价值：** 浏览器里跑科研 Python，统计方法对标 GraphPad Prism 常用项。

怎么讲：

- 流程图加 **Custom code** 步骤，上游表进去，出来可以是表、文件或图
- 预装科学包：pandas、numpy、scipy、scikit-learn、rdkit、statsmodels、biopython、lmfit、matplotlib、seaborn、plotly 等
- **statlib**：20 个常用方法，一条调用即可，不必从零写检验代码

statlib 可点名的能力（按客户领域挑 3～5 个，不要背完）：

| 客户场景 | 方法 |
| --- | --- |
| IC50 / EC50 / 四参数 | 非线性回归 4PL/5PL、Michaelis-Menten |
| 标准曲线反算浓度 | standard curve interpolation |
| 组间差异 | t 检验、单因素 ANOVA（Tukey / Dunnett 等） |
| 数据质量 | 描述统计、正态性、离群值（IQR / Grubbs / ROUT） |
| 曲线特征 | AUC、平滑/求导、复孔均值 SD/SEM/CV |
| 相关与一致 | Pearson/Spearman、Bland-Altman、ROC |

步骤内带 **Code AI**：用自然语言生成/修改脚本，会话按步骤隔离，不会串到别的分析。

**边界：** 没有独立的「Prism 点选统计」界面；统计发生在 Custom Code + 技能（Skills）里。仓库里另有一套 Streamlit 参考实现，**不是** Insight 产品界面，不要打开给客户。

### 4.8 AI 分析

**价值：** 科学家用中文说目标，系统按计划调用导入、清洗、作图、看板、报告。

客户能看到：

- 全局 AI 抽屉（可停靠）
- 上传附件、@ 引用当前表、快捷指令
- 计划清单、工具轨迹、图表/表产物卡片
- 需要确认的操作会停下来让用户批准（也可设为全部允许）
- 「完成后生成报告」勾选
- 设置里：模型（OpenAI 兼容）、Skills、MCP、记忆

预置领域技能（跟客户说「我们按你们的实验类型教过 AI」）：

| 技能 | 一句话 |
| --- | --- |
| 实验室通用流程 | 探查 → 清洗 → 连接 → 作图 → 结论 |
| 抗体发现 | 结合筛选、SPR/BLI、克隆排序 |
| 细胞株开发 | 滴度、活率、稳定性 |
| 体外生物分析 | 剂量反应、4PL/EC50、孔板热图 |
| 体内药效与耐受 | 瘤体积、体重、分组比较 |
| 作图最佳实践 | 怎么配现有图种 |
| statlib 五件套 | 组间比较 / 剂量反应 / 分布离群 / 信号相关 / ROC 与一致性 |

**诚实讲法（重要）：**

- 简单到中等任务（单表、字段清楚、目标明确）演示成功率高，适合现场。
- 复杂多表、SOP 长文、多 Sheet 脏 Excel：AI 会出计划并尽量执行，但**科学家仍需在 Workspace 确认图和步骤**。不要承诺「扔一份 CRO 包就能无人值守出完整 IND 包」。
- AI 必须走产品后端；只开前端、没有模型配置时，当普通工作区用即可。

### 4.9 分析报告

**价值：** 分析结束有一份可预览的科研风格 HTML 报告，而不是只在聊天窗口里一段话。

- 流程图上的**独立节点**（不必连线）
- 模板：通用科研 / 抗体筛选 / 数据复盘
- 章节里可嵌已有表和图，AI 可写图注与解读
- 可人工改章节，也可让报告助手按 JSON 结构生成

适合：课题小结、项目会材料初稿、内部评审。正式申报材料仍由客户质量体系把关。

## 5. 典型业务场景（方案书可直接贴）

### 场景 A｜抗体发现：从 ELISA 到候选排序

1. 导入 ELISA 初筛表 + SPR 动力学表  
2. 过滤对照孔，按 `clone_id` Join  
3. 散点：KD vs 表达量/OD，按 isotype 着色  
4. 柱状对比 Top 克隆  
5. 生成抗体模板报告，关键图钉到看板  

**Demo 数据：** 首页「生成项目示例数据」。

### 场景 B｜体外效价：96 孔板剂量反应

1. 一键 Demo → Plate 96 dose-response  
2. 散点或折线：浓度 vs 响应，开 **4PL**  
3. 看 MODEL TABLES（IC50 等）  
4. 需要组间检验时加 Custom Code + statlib  

### 场景 C｜工艺/信息化：库表刷新 + 周会看板

1. SQL 连接客户库（或演示库）拉批记录  
2. 过滤批次、计算列  
3. 看板钉趋势图 + 大数字 KPI  
4. 定时刷新，下游步骤过期后重跑  

### 场景 D｜「先让 AI 跑一版」

1. 打开示例分析或上传一张干净 CSV  
2. AI：「按抗体发现技能，过滤对照，画 KD 对比柱状图，完成后出报告」  
3. 看计划 → 产物卡 → 点进 Workspace 人工微调 STYLE

## 6. 推荐 Demo 脚本

### 6.1 十五分钟（管理层 / 第一次见面）

目标：让对方感到「这是实验室分析工作区，不是 BI 报表」。

| 分钟 | 动作 | 口播 |
| --- | --- | --- |
| 0–2 | 首页 → 一键 Demo | 「三分钟进入真实分析，不是空壳」 |
| 2–6 | 打开剂量反应表 → 创建散点 → 4PL → 导出 PNG | 「科学家熟悉的拟合，在浏览器里完成」 |
| 6–9 | 切 Flowchart | 「过程留得住，换人也能复现」 |
| 9–12 | 侧栏切看板 → 新建 → 把表和图钉上去 → 拖布局 | 「周会只看这一页」 |
| 12–15 | 打开 AI 抽屉，问一句「这张表的响应随浓度怎么变化」 | 「AI 是加速器，图仍在工作区里可改」 |

### 6.2 三十分钟（科学家 / 部门负责人）

在 15 分钟基础上加：

1. **生成项目示例数据**，打开带 Join 的抗体分析，沿流程图走一遍  
2. 表上开「编辑数据」，改一个数，指出下游会过期  
3. Excel 导入或 Combine 点一下（不必真连客户库）  
4. Custom Code：说明「Prism 统计在这里用 Python 跑，包已预装」  
5. AI 设置里扫一眼 Skills 名单（抗体 / 体外 / 体内）  
6. 报告节点预览一页  

现场避坑：

- 不要从左侧点「注册 / 化合物 / 序列」——会提示即将上线。  
- 不要承诺现场连客户生产库（防火墙、账号、字段 anonymize 先对齐）。  
- AI Demo 用字段清楚的表示例；复杂附件留到技术交流。  
- Custom Code 前确认 Worker 是绿的，否则改讲原生 4PL，不要现场排错。

## 7. 竞品对照（怎么说差异，不攻击）

| 客户正在用 | 认同他们 | 我们多出来的 | 不要贬低成 |
| --- | --- | --- | --- |
| **Excel** | 改数最快、人人会 | 步骤可审计、科学图种、4PL、看板、AI | 「Excel 不能用」 |

推荐收口句：

> 「Excel 负责随手算，Prism 负责发表级统计图，ELN 负责实验记录。Insight 负责**从原始表到可复现结论**这一段：清洗、作图、统计脚本、报告和看板在同一个分析里。」

若客户已有 ELN：强调我们当前交付的是**分析层**，Registry / Plate 直连是平台后续，可用 CSV/Excel/SQL 对接现状。

## 8. 客户常问

**Q：数据存在哪？安不安全？**  
企业部署：分析与看板内容进客户侧数据库（MariaDB），服务部署在客户内网或指定云。产品规则是存**数据内容**，不把原始上传文件当长期档案。浏览器也可本地试用（IndexedDB），正式项目建议走服务端。

**Q：能不能替代 Prism？**  
作图 + 常用拟合（含 4PL）以及 statlib 的 t 检验 / ANOVA / 非线性回归等，覆盖日常科研统计的一大部分。发表级排版、部分冷门检验、实验室已验证的 Prism 模板，建议并行期对照，不要第一天要求 100% 替换。

**Q：AI 用哪家模型？数据会不会出域？**  
兼容 OpenAI 协议，模型地址和 Key 由客户配置。可以接到客户已审批的私有化模型。Skills / 记忆按用户隔离。具体出域以客户网络和所配模型服务为准。

**Q：能不能和 LIMS / ELN / 注册库打通？**  
现在最稳的是：**文件**（CSV/Excel）和 **SQL**。注册库、孔板库在界面有入口但未开通。方案里写成「分析层先落地，主数据对接按项目排期」。

**Q：权限和审计呢？**  
当前演示为用户切换与 AI 操作确认，**不是**完整 IAM / 电子签名 / 审计日志。GXP 客户把权限、审计、电子签名单独立项，不要用演示账号体系回答「已符合 21 CFR Part 11」。

**Q：多少人能同时用？**  
分析与看板可多用户通过服务端共享同一套数据。不是 Google Docs 式同格实时共编。适合「各自做分析、看板上会」的实验室协作。

**Q：支持中文吗？**  
产品界面与 AI 交互以中文为主，科学图表配置项保留国际通用术语（Bar、4PL、Join 等），科学家一般能接受。
