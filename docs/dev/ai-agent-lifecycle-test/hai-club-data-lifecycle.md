# 02 当前流程与数据生命周期

# 文档目的

本文档用于梳理 HAI Club 当前重点业务场景中的真实研发流程，并明确在每个环节产生、流转和需要沉淀的数据。

# 当前适用场景

当前优先梳理的业务场景是抗体亲和力改造。

典型项目从已有抗体序列或结构出发，通过算法设计、候选筛选、表达实验、BLI 亲和力检测和多轮迭代，寻找亲和力较初始序列明显提升的 Candidate。

# 详细流程说明

## 项目输入与结构准备

项目输入通常包括靶点/抗原信息、初始抗体信息、抗体序列或抗体结构。

多数情况下输入是**抗体序列**；如果项目已有可靠结构，则可以直接进入基于结构的设计或评估流程。

如果缺少结构，**可能需要先通过结构预测生成候选结构**。

## 人工挑选

- 需要可视化看到结构，进行旋转拖动放大等基础操作
- 每次都只关注参考结构（WT）
- 每次只关注突变位点氨基酸附近5A的氨基酸和结构。

## 送检序列的选择策略：单点突变、组合突变与候选生成

- 第一轮：通常会从单点突变结果中选择topN进入实验。
  - 更详细来说，由于当前会用到4种（或更多）算法，一般会选每个算法推荐的topN
  - 另外，如果有的结果被多个算法同时推进（满足阈值），但不在topN中，也会被考虑。这种被称为Vote
  - 一般来说，最终会选择60-70个候选（取决于预算）
- 第二轮：
  - 组合突变
    - 选择湿实验中表现较好的 topN单点进行组合2-10个突变的排列组合，将这些组合再做一轮算法打分。选择topN或者Vote组合
  - 单点突变
    - 用湿实验的结果对模型（evolvepro）进行微调，对单点突变结果重新进行打分。再挑选topN单点或者Vote
    - 直接选择第一轮单点突变结果中的次topM个单点结果
- 第三轮：选择第二轮湿实验中表现较好的单点/组合，再次进行排列组合。选择topN或者Vote组合

## 送检与 CRO 实验

- 表达实验主要由百英完成，百英表达结果可能会生成后续通用订单需要的信息，例如等电点、理论分子量等。
- 亲和力检测主要由通用完成，BLI 是核心的检测方式。
  - 一般只有参考会做多浓度
  - 表现比较好的可能会做SPR（金标准）
  - 大部分都是用单浓度
  - 另外，需要注意

:::
**特殊检测方案：单价抗体策略**

**触发条件**

**已确认：** 当起始分子（阳性对照）亲和力过高（>检测上限）时，无法有效评估优化效果，此时启用单价抗体策略。

**实施流程**

构建单价抗体（Fab–Fc）用于亲和力检测，降低价态从而减弱结合强度，使其落入检测范围。

同步表达双价抗体（天然形式），用于后续体内/体外药效验证。

**已确认：** 交付给项目组的是双价抗体及其序列，单价抗体仅为中间检测工具。

**决策依据**

实验前先通过Bio-Layer Interferometry（BLI）测试阳性对照：

固定抗原和固定抗体均测不到 → 使用单价抗体；

任一方式可测到 → 使用常规双价抗体。

**现状统计**

**已确认：** 近期完成的5个项目中，有2个采用了单价抗体策略。
:::

## 实验结果处理

- 表达实验
- BLI 亲和力结果
  - 可能存在重复实验或多批次结果，需要定义如何取代表值（目前一般会取平均值，但需要关注到两次的差异，比如如果两次差异差距超过2-3倍，需要进行提醒）
  - 主要关注Kd
  - 需要保留实验图谱，如果拟合曲线不好，数据准确性存疑

当前流程中，实验结果会被整理到汇总表中，用于判断是否达到项目目标。如果至少有一个 Candidate 的 BLI 湿实验结果达到初始序列亲和力的 X 倍提升，则可认为项目目标达到；否则进入下一轮设计。

## 下一轮设计与项目交付

如果第一轮未达标，通常会基于[策略](https://alidocs.dingtalk.com/i/nodes/EpGBa2Lm8azv5qjaSE0mb1RgWgN7R35y?utm_scene=person_space&iframeQuery=anchorId%3Duu_mpdw2j731e05non5e81)进行序列挑选进入下一轮。 

如果项目达标，则 Candidate 会交付项目团队。后续项目团队产生的体外药效、体内药效等数据目前不一定稳定回流到算法团队或统一系统中。

## 当前的协作方式

- 分工表

| 人员   | 负责项                               |
| ---- | --------------------------------- |
| 实验员A | FoldX 和 FlexDDG的计算、筛选             |
| 实验员B | ProteinMPNN和ESMIF（或其他新算法）的计算、筛选   |
| 实验员C | 拿到待检序列，按照供应商模板进行表达和亲和力的送检。并获得送检结果 |

- 协作
  - 实验员A和实验员B分别进行计算。
    - 实验员A只关注抗原抗体相互作用界面的氨基酸突变
    - 实验员B会穷举全序列突变
  - 二者会将各自的结果合并到一个excel表中，然后分别进行标识与vote，最终共同选择出送检序列（一般是60-70个，取决于预算）【此处有协作难点，excel协作不方便】
  - 在第一轮中，由于foldx和flexddg在预测单点突变的表现相对不佳，通常会以实验员B的计算结果为主。比如，实验员A只推荐25个，实验员B推荐剩余的数量。
  - 在组合突变中，由于flexddg的表现会比较好，所以在挑选时会相应增加实验员A推荐的比例。foldx在组合突变中一般不用。
